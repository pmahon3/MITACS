# Provenance Requirements Matrix

Research/design deliverable (Task 32). Enumerates every downstream
conclusion the project may put forward for scrutiny and, per claim,
which provenance it needs vs currently has. **No machinery is built
here** — this drives a prioritized implementation decision *after*.

## Provenance axes (kept distinct — different mechanisms)

- **R — Reproducibility**: an independent re-run yields the same numbers
  (needs: pinned code commit, data fingerprint, env/lib versions, RNG
  seeds, cache keyed to code not wall-clock).
- **A — Auditability**: a reviewer traces a claim to the exact code+data
  that produced it *without re-running* (needs: committed result
  artifact with a provenance header; the stdout that the claim quotes).
- **I — Integrity / tamper-evidence**: proof a result was not altered
  after the fact (needs: content hash, append-only, write-once).
- **X — External/recovered-data provenance**: the source of any data not
  generated by this pipeline is pinned and its extraction rule fixed
  (needs: source ref + extraction spec + a content fingerprint).

## Claim grades

- **CLAIM-GRADE**: may appear in the writeup / be defended to
  reviewers. Must meet R+A+I (and X if it uses external data).
- **METHOD/DESIGN**: an architectural or methodological assertion
  (e.g. "the GL selector is degenerate"); needs A+I, R where it rests
  on a computation.
- **INSPECTION-ONLY**: explicitly exploratory; findings in memory, not
  to be quoted as results. Needs A (so a reader knows it *was*
  exploratory and how it was produced) — nothing more. Over-hardening
  these is itself a mistake.

## Synthesis — the actual gaps, prioritized

1. **No claim-grade artifact carries a provenance header.** C1, C2, C3,
   C4 are quotable but none records {git SHA, frozen_spec hash,
   numpy/edynamics versions, RNG seeds, run timestamp, input data
   fingerprint}. **Highest leverage**: one small standard provenance
   header + a `make_result()` helper that every result file (existing
   and future) is regenerated through. Closes A+I for C1-C4 at once.
2. **The `/tmp` forecast cache breaks reproducibility-by-construction**
   for the honing chain (C6/C7). If any C7 finding is promoted to
   claim-grade it MUST be re-run through committed code with a
   content-keyed (not /tmp-fixed) cache and the output captured.
3. **Theory correspondence (C3) is memory-only.** It is the project's
   most distinctive contribution and currently has the WEAKEST
   audit/integrity (mutable note, no repo artifact). Promote to a
   committed, hashed `THEORY_CORRESPONDENCE.md` for the writeup.
4. **Synthetic gate outputs (C4) are not captured.** Cheapest fix
   (re-run once, save with header) and high value — C4's R is already
   strong, only A+I missing.
5. **External-data access dates unstamped (C2, C6).** IESO restructures
   its public site (proven this session by 404s); any IESO-archive
   claim must record the access date + the exact paths/extraction.
6. **Grade labels not on artifacts.** C6/C7 risk mis-citation as
   results. Every artifact needs a one-line grade banner
   (CLAIM-GRADE / METHOD / INSPECTION-ONLY).

## Recommended provenance tiers (the decision this enables)

- **Tier-1 (do before Goal 4 writeup)**: standard provenance header +
  `make_result()` regeneration path applied to C1, C2, C3, C4; promote
  C3 to a committed hashed document; stamp IESO access dates. This is
  the finite checklist that makes the writeup defensible.
- **Tier-2 (only if a C7 finding is promoted)**: close the /tmp-cache
  reproducibility hole (content-addressed cache + captured output).
- **Tier-0 (no-op, explicit)**: inspection-only artifacts (C6, residual
  C7) get a grade banner ONLY. Further hardening = over-engineering.

C5 is the existing template; the work is "raise C1-C4 to C5's bar",
not invent new mechanisms.
